# =============================================================================
# tabgen "readers" — Python analysis pipeline dependencies
# =============================================================================
# The reader package (file_analyzer/) has a PURE-STDLIB CORE: RepositoryAnalyzer, the
# router, all {Lang}Analyzers, SchemaAnalyzer, DatabaseAnalyzer, the archive and
# machine-code/binary forensic layers, and the SQLite db-generator all run with
# NOTHING installed but CPython. `from file_analyzer import AnalysisEngine` and a full
# repository -> SQLite run work on a bare interpreter.
#
# Every package below is therefore OPTIONAL. Each is imported lazily and guarded
# (inside a function / try-except); when it is absent the corresponding format
# still analyzes but DEGRADES to a bounded metadata/"partial" profile instead of
# a full deep parse. Installing a package upgrades those files from "partial" to
# "ok" (richer schema, real statistics, decoded frames) — it never changes
# routing and never turns a real parser into a stub.
#
# Pinning: intentionally unpinned. The guards tolerate any modern release; pin in
# a downstream lockfile if you need reproducibility. A few packages (GDAL,
# python-snappy) require system libraries — see the notes on those lines.
#
# Install everything:      pip install -r requirements.txt
# Minimal / core only:     install nothing (stdlib is enough)
# =============================================================================

# =============================================================================
# Background repository monitor (file_analyzer/monitor/, `python -m file_analyzer monitor <repo>`)
# =============================================================================
# The always-on monitoring + incremental-update layer is PURE STDLIB with NO new
# hard dependency: change detection is an os.walk + hashlib snapshot/diff, the
# 16-deep FIFO diff record is plain SQLite (WAL), the concurrent re-analysis
# worker pool has a stdlib `concurrent.futures` fallback, and process management
# (signals, PID file, atexit, daemon threads, child reaping) is all stdlib.
# There is NOTHING to install for the monitor: it detects changes by polling
# (os.walk + hashlib snapshot/diff on a fixed cadence), so there is no watcher
# library to add. The Go worker pool (file_analyzer/monitor/go/) is an optional speed-up
# for very large change sets, built on demand with the `go` toolchain (not a pip
# package); without Go the pool transparently uses the concurrent.futures path.
#
# The monitor's two DURABLE dumps -- the continuous change log and the
# session-summary dump (file_analyzer/monitor/change_log.py + session_log.py) -- also
# default to local SQLite (still nothing to install). They can instead live on a
# REMOTE SQL server by passing a connection URL; only then do you need a driver,
# imported lazily so the core stays stdlib-at-import:
#   PostgreSQL:  pip install "psycopg[binary]>=3.1"   (or:  .[monitor-postgres])
#   MySQL/Maria: pip install "PyMySQL>=1.1"           (or:  .[monitor-mysql])

# =============================================================================
# Document-intelligence engine (DocumentParser: Parts A / B / C)
# =============================================================================
# The document-analysis engine (file_analyzer/document/) is ALSO pure-stdlib at its core:
# Part A static metrics, the Part-B agent+code loop transport (agent_mcp.py) and
# ALL Part-C evaluation metrics (evaluation_metrics.py -- CER/WER/BLEU/METEOR/
# chrF/ROUGE/TEDS/mAP/REDS/ANLS/ECE/PSI, and a deterministic RAG judge) are
# implemented with the standard library alone. The packages below are OPTIONAL
# accelerators / cross-validators / reference backends for the spec's tooling
# table (docs/document-engine-libraries.md, spec §6). The engine runs and emits
# real rows WITHOUT any of them; install a package to upgrade a layer from the
# stdlib implementation to a richer / faster / reference one. Several A-layer
# tools are system binaries, not pip packages (Tesseract, qpdf, exiftool,
# veraPDF) -- see the docs file for those.
